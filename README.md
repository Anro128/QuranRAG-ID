# QuranRAG-ID

**English** | [Bahasa Indonesia](README.id.md)

A Retrieval-Augmented Generation (RAG) question-answering app for the Qur'an in Indonesian.
Every answer cites its source verses (`[QS surah:ayah]`), and Arabic text is always taken from the
database, never generated by AI.

## Features

- **Hybrid search**: `multilingual-e5-base` embeddings + BM25 with an Indonesian stemmer, fused with RRF.
  At runtime the query encoder uses ONNX int8, so the server does not need torch.
- **Direct references**: `QS 2:255`, `Al-Baqarah ayat 255`, `albaqarah 255`, `ayat kursi`, `surat yasin ayat 1`.
- **Term normalization** to the spelling used by Indonesia's Ministry of Religious Affairs (Kemenag)
  (`sholat` → `salat`, `bunga` → `riba`, etc.).
- **AI answers via DeepSeek** with citation validation: citations to verses outside the retrieved sources are flagged.
- **Login** with username + password; chat history is not stored.
- Still usable as a verse search engine without an API key.

## Requirements

| | Building data & indexes | Running the server |
|---|---|---|
| Software | Python 3.11+, Node.js 20+ | Docker + Compose (or Python 3.11+ without Docker) |
| RAM | ~8 GB | 1 GB + 1–2 GB swap (app ~650 MiB, peak ~830 MB) |
| Disk | ~5 GB (torch, models, data) | ~1.5 GB (image ~1 GB + data ~350 MB) |
| Other | internet access to download datasets & models | [DeepSeek](https://platform.deepseek.com) API key (optional) |

Data and indexes only need to be built **once** on a laptop/PC; the server then uses the results.

## Installation

The commands below use bash (Linux/macOS/Git Bash). For Windows PowerShell, see the notes in each step.

### 1. Get the code and create a virtualenv

```bash
git clone https://github.com/Anro128/QuranRAG-ID.git
cd QuranRAG-ID
python -m venv .venv
source .venv/bin/activate          # PowerShell: .venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -e ".[index]"          # runtime + build tools (sentence-transformers, onnx)
```

> A server that only runs the app needs just `pip install -e .` (no torch). See [Deploy to a VPS](#deploy-to-a-vps-docker).

### 3. Configure

```bash
cp .env.example .env               # PowerShell: Copy-Item .env.example .env
```

At minimum, set `DEEPSEEK_API_KEY`. All variables are listed under [Configuration](#configuration).

### 4. Build data and indexes

Run in order (about 1 hour in total, mostly embedding):

```bash
python -m src.ingest.download      # download public datasets to data/raw/
python -m src.ingest.normalize     # build data/processed/quran.db
python -m src.ingest.validate      # check 114 surahs & 6,236 ayahs, cross-checked with Tanzil
python -m src.index.chunker        # split ayahs + tafsir into chunks
python -m src.index.bm25_index     # BM25 index
python -m src.index.embed          # embeddings into LanceDB (~30–60 min on CPU)
python -m src.index.export_onnx    # ONNX int8 query encoder -> data/models/e5-base-int8/
```

### 5. Build the frontend

```bash
cd web
npm install
npm run build                      # output in web/dist/, served directly by the backend
cd ..
```

### 6. Create an account

There is no public sign-up; accounts are created from the CLI (password of at least 8 characters, prompted interactively):

```bash
python -m src.auth create-user <username>
```

## Running

```bash
uvicorn src.api:app --port 8000
```

Open http://localhost:8000 and log in.

### Development mode

To work on the frontend with hot reload, use two terminals. Vite proxies `/api` requests to port 8000.

```bash
uvicorn src.api:app --reload --port 8000     # terminal 1: backend
cd web && npm run dev                        # terminal 2: frontend -> http://localhost:5173
```

When you are done changing the frontend, run `npm run build` so the changes are also served on port 8000.

### Managing accounts

| Command | Purpose |
|---|---|
| `python -m src.auth create-user <username>` | create an account |
| `python -m src.auth passwd <username>` | change password (also signs out all of that account's sessions) |
| `python -m src.auth delete-user <username>` | delete an account |
| `python -m src.auth list-users` | list accounts |

### Tools

```bash
python search.py "sabar menghadapi musibah"   # test search from the terminal
python -m eval.run_eval --detail              # evaluate search on the golden set (66 questions)
python -m eval.run_eval --configs hybrid+sin --llm   # same, with DeepSeek keyword expansion
```

## Deploy to a VPS (Docker)

The Docker image contains both the backend **and** the frontend (built inside the image), without torch.
The `data/` folder (database, indexes, ONNX model, accounts) is not part of the image; it is mounted
as a volume.

### 1. Prepare the VPS

Install Docker Engine + the Compose plugin, then get the code:

```bash
git clone https://github.com/Anro128/QuranRAG-ID.git
cd QuranRAG-ID
cp .env.example .env               # set DEEPSEEK_API_KEY
```

### 2. Send data from the build machine

`data/` is not in git. From the build machine (e.g. WSL), send the output of [Build data and indexes](#4-build-data-and-indexes):

```bash
rsync -avzR --progress --exclude 'api.log' data/processed data/models <vps-host>:~/QuranRAG-ID/
```

Replace `<vps-host>` with an SSH alias or `user@ip`, and adjust the destination path to where you cloned the repo on the VPS.

### 3. Build and run

```bash
docker compose up -d --build
docker compose exec app python -m src.auth create-user <username>
```

The container only listens on `127.0.0.1:8001`; public access goes through a reverse proxy in front of it
(an example Nginx config is in [deploy/nginx/](deploy/nginx/)). When served over HTTPS, set `COOKIE_SECURE=true`.
Check from the VPS: `curl http://127.0.0.1:8001/api/health`.

### Everyday commands

| Command | Purpose |
|---|---|
| `docker compose logs -f app` | view logs |
| `docker compose ps` | container status & health |
| `docker compose restart app` | restart (e.g. after editing `.env`) |
| `git pull && docker compose up -d --build` | update to the latest code |
| `docker compose exec app python -m src.auth <command>` | manage accounts (see [Managing accounts](#managing-accounts)) |
| `docker compose down` | stop |

### Notes

- **Example Nginx config** ([deploy/nginx/](deploy/nginx/)) disables buffering for `/api/chat` so answers stream
  progressively, and overwrites `X-Forwarded-For` with the real client IP so the per-IP login limit cannot be
  bypassed. The container trusts this header (`FORWARDED_ALLOW_IPS` in `docker-compose.yml`) because its port
  is only open on localhost.
- **Direct access via IP** (`http://IP:8001`, without a reverse proxy): change the port in `docker-compose.yml` to `"8001:8000"`, set
  `COOKIE_SECURE=false` (with `true`, logins are not kept over HTTP), and open port 8001 in the Azure firewall.
  Ports published by Docker are **not** subject to `ufw` rules. Revert when you are done testing.
- **Memory**: the container uses ~650 MiB (peak ~830 MB, measured with 1 vCPU). On a 1 GB VPS enable
  1–2 GB of swap, since the OS and Docker themselves also need ~250 MB.
- **Single worker**: the image runs one uvicorn process. Do not add `--workers`: each worker loads its own
  copy of the model and indexes. One worker still serves many users concurrently, because each request runs in
  its own thread and spends most of its time waiting for DeepSeek.
- **Write permission**: the container runs as UID 1000 and writes `data/app.db`. If your VPS user is not
  UID 1000, run `sudo chown -R 1000:1000 data`.

### Without Docker

You can also run it directly with Python on the VPS: also copy `web/dist/`, then `pip install -e .` (runtime
dependencies only) and `uvicorn src.api:app --host 127.0.0.1 --port 8000`, with the same notes about a single
worker, swap, and a reverse proxy.

## Configuration

Everything is set in the `.env` file:

| Variable | Default | Description |
|---|---|---|
| `DEEPSEEK_API_KEY` | *(empty)* | DeepSeek API key. Empty = verse search engine mode only |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | API endpoint (OpenAI-compatible) |
| `DEEPSEEK_MODEL` | `deepseek-chat` | DeepSeek model name |
| `EMBED_MODEL` | `intfloat/multilingual-e5-base` | embedding model (must match the one used to build the index) |
| `EMBED_BACKEND` | `auto` | `auto` (ONNX if available), `onnx`, or `torch` |
| `ORT_THREADS` | `0` | ONNX Runtime threads; `0` = automatic (cores available to the process, max 4) |
| `COOKIE_SECURE` | `false` | `true` when the app is served over HTTPS |

## API

| Method | Path | Description |
|---|---|---|
| GET | `/api/health` | backend and LLM status (public) |
| POST | `/api/auth/login` | body `{username, password}`; sets an httpOnly session cookie (valid for 7 days) |
| POST | `/api/auth/logout` | delete the session |
| GET | `/api/auth/me` | currently logged-in user |
| POST | `/api/chat` | login required. Body `{query, history, use_llm_expand}`; SSE response: `retrieval` → `delta`* → `final` (or `error`) |
| GET | `/api/ayat/{surah}/{ayat}` | login required. One full ayah (Arabic, translation, tafsir) |

Security: passwords are hashed with scrypt, session tokens are stored only as hashes, and login is locked for
60 seconds after 5 failures per IP + username. Chat history is **not stored** on the server or in the browser.

## Project structure

```
src/ingest/       dataset download, normalization to SQLite, validation
src/index/        chunking, BM25, embeddings (LanceDB), ONNX export & encoder
src/retrieval/    reference parser, router, hybrid search, query expansion, DB access
src/generation/   DeepSeek client, prompts, citation validator, RAG pipeline
src/resources/    sinonim.json (synonyms), alias_surah.json (surah aliases), stopwords_id.txt
src/api.py        FastAPI backend (SSE)
src/auth.py       login, sessions, account management CLI
Dockerfile        runtime image (frontend + backend, no torch)
docker-compose.yml  service on 127.0.0.1:8001, data/ volume
deploy/nginx/     example Nginx config (reverse proxy)
eval/             golden_set.jsonl, run_eval.py
web/              React + Vite + TypeScript frontend
search.py         search test CLI
```

## Limitations

This app is not a substitute for religious scholars and does not issue fatwas. AI answers can be wrong;
always check the cited verses and tafsir.
